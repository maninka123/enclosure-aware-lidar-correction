Model & assumptions

Equations, coordinates, material sources and research scope.

About these results

This online app is a simplified, interactive implementation inspired by the paper's MATLAB experiments. Its configurations, assumptions and calibration workflow are not identical to the paper, so numerical results and figures may differ. Use it to explore refraction and correction; it is not an exact reproduction of the published results.

01

Meet the inner surface

A ray travels from the source to the inner sphere. The surface normal points radially away from the dome centre. A centred source hits normally and has no angular deflection.

P = O + t d   ·   |P − C| = R
02

Apply Snell’s law twice

The ray bends toward the normal entering a higher-index material, then bends again on leaving it. The two normals differ, so the bends do not generally cancel.

n₁ sin θ₁ = n₂ sin θ₂

When no transmitted ray exists, total internal reflection is reported instead of drawing a fictitious ray.

03

Choose the range interpretation

Direction only (paper-style LUT) keeps the measured radius and changes only the outgoing direction. Geometric path treats the measured radius as the total physical distance through the inside medium, wall and outside medium. Optical path reconstructs the endpoint from the time-of-flight optical length and is the recommended starting point for ToF LiDAR when the sensor's range convention and refractive indices are known.

P = Pouter + Loutside dexit

Optical mode assumes nref r = Σ nᵢ Lᵢ. A sensor’s reported time-of-flight range already includes the round-trip factor; do not halve it again. There is no universal best option: select the model that matches how the sensor produced its range.

04

Use the right material data

Refraction uses phase refractive index. Pulse timing depends on group index, which may differ. This app uses the same configured index for both, matching the simplified Python model. For precision range work, characterize dispersion and instrument bias.

Nominal polymer values are starting points, not validated infrared values or structural recommendations.

Material presets & sources

Air defaults to the project's legacy constant. Outside-medium indices are editable. Surface reflection losses, absorption, scattering, coatings, finite beam width, housing rims, nonconcentric surfaces, detector offsets and multipath are not modeled.

Coordinate conventions

All physics runs in metres. Enclosure controls use millimetres; scene controls use metres. Sensor +Z is forward. Roll, pitch, yaw form the right-handed active rotation Rz Ry Rx. Selected-beam and LUT XZ/YZ angles use atan2(Z,X) and atan2(Z,Y): 0° is the positive lateral axis, 90° is sensor +Z, and 180° is the negative lateral axis. Deflection sweeps use 0° as the first named axis and 90° as the second: XZ sweeps from +X to +Z; YZ from +Y to +Z; XY from +X to +Y.

Only the upper shell (relative to the centre Z) is active in hemisphere mode. A source can lie below the equatorial plane if it remains inside the sphere; no base plate is simulated. Python configuration JSON preserves the exact rotation matrix.

Angular lookup table (LUT)

A reusable correction table for one optical configuration.

A LUT samples the analytical dome ray tracer on an XZ/YZ angular grid. Point correction then uses bilinear interpolation between valid grid nodes, which is faster than tracing both spherical interfaces for every point. The paper-style LUT changes direction while preserving the measured point range.

0° +X or +Y 90° sensor +Z forward 180° −X or −Y

A LUT is configuration-specific. Changing dome dimensions, source position, rotation, aperture, or refractive indices makes it stale. Imported LUTs are accepted only when their stored configuration hash matches the current setup.
